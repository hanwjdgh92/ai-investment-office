# 2단계 재정의: 매매 시그널 생성 (크립토 파일럿) Design Spec

**작성일:** 2026-08-09
**배경:** README.md 로드맵은 원래 3단계였다 — 1단계(정보수집·리포트, 완료), 2단계(매매 신호 생성 +
승인 후 실행), 3단계(완전 자동 매매, 거래소 API 자동 주문). 그러나 Claude Code 세션 안에서는 실제
금융 거래 실행(거래소 API 호출, 자금 이동)을 절대 수행할 수 없다는 운영 제약이 있다. 이 제약을 반영해
로드맵을 다시 정의한다.

## 결정 사항

- **3단계(완전 자동 매매) 삭제.** 거래소 API로 자동 주문을 넣는 기능은 이 프로젝트 범위에서 만들지
  않는다.
- **2단계를 재정의**: AI는 매매 시그널(진입가·목표가·손절가·포지션 크기)과 리스크 검토까지만 생성한다.
  실제 주문은 100% 사람이 거래소 앱/사이트에서 직접 클릭해서 넣는다 — AI나 스크립트가 거래소 API를
  호출하는 경로는 이번 범위에 없다.
- 기존 오피스 UI에 이미 잠금 상태로 존재하던 Trigger(TRADING 존, 시그널 생성)와
  Maverick/Guardian/Balance(RISK MGMT 존, 공격적/보수적/중립 리스크 검토)를 2단계 담당으로 흡수한다.
  원래 이들의 안내 문구는 각각 "2단계/3단계에서 합류 예정"으로 나뉘어 있었는데, 3단계가 사라지므로
  넷 모두 2단계에서 함께 잠금 해제된다.
- **크립토부터 파일럿.** 국내주식/해외주식 Trigger는 이번 범위에 포함하지 않는다(추후 별도 spec).

## 목표

- `/scheduled-analysis` 실행 시 크립토 데스크 파이프라인 끝에 시그널 생성 + 리스크 검토 단계를
  추가해, 관심 코인마다 방향(매수/매도/관망)·진입가·목표가·손절가·포지션 크기(%)·근거를 산출한다.
- 결과는 `reports/YYYY-MM-DD.md`에 새 섹션으로 저장되고, 오피스 UI에서 TRADING/RISK MGMT 존 카드로
  표시된다(기존 애널리스트 카드와 동일한 클릭→모달 상세 패턴).
- README.md 로드맵 문서를 새 2단계 정의로 갱신한다.

## 범위 밖 (Non-goals)

- 거래소 API 연동, 실주문 실행, 주문 상태 추적 — 전부 사람이 수동으로 함.
- 포지션 크기의 실금액 계산(계좌 잔고 연동) — 이번엔 "총자본 대비 %"만 제시, 실금액 환산은 사람 몫.
- 국내주식/해외주식 시그널 — 크립토 파일럿 검증 후 별도 spec으로 확장.
- 시그널 이력 추적, 손익 백테스트, 알림(푸시/문자) — 이번 범위 아님.

## 아키텍처

기존 크립토 데스크 파이프라인(Candle/Proto/Vibes 병렬 분석 → Node 리서치 종합) 뒤에 이어붙인다.
새로운 파이프라인 유형을 만들지 않고 기존 "병렬 분석 → 종합" 패턴을 재사용한다.

```
Candle/Proto/Vibes (기존, 병렬 분석)
  → Node (기존, 리서치 종합 — 강세/약세 논거 저울질)
  → Trigger (신규, 시그널 생성): Node의 리서치 노트 + 최신 시세/지표를 받아
    코인별 진입가·목표가·손절가·포지션%(리스크 기준)를 숫자화
  → Maverick/Guardian/Balance (신규, 병렬 리스크 검토): Trigger의 제안을 각각
    공격적 확대/보수적 축소/중립 관점에서 검토
  → The Boss (기존, 종합 리포트) 최종 요약에 매매 시그널 섹션 반영
```

## 데이터 흐름 & 시그널 포맷

- **입력**
  - Node의 리서치 노트(`reports/*.md`의 "Node - 크립토 리서치 종합" 섹션)
  - `data/crypto_YYYY-MM-DD.json` (현재가, RSI, 이동평균)
  - `config/watchlist.yaml`의 `crypto` 목록(대상 코인)
- **Trigger 출력** (코인별):
  - 방향: 매수 / 매도 / 관망
  - 진입가, 목표가, 손절가
  - 포지션 크기: 총자본 대비 %
  - 근거: Node 리서치 인용
- **Maverick/Guardian/Balance 출력**: Trigger 제안에 대한 관점별 검토 + 최종 권고 수치(저울질 결과)
- **저장**: `reports/YYYY-MM-DD.md`에 "매매 시그널" 섹션 추가. 기존 리포트 파싱 패턴
  (`office_data.py`의 `report_sections` 매칭)을 그대로 재사용 — 새 파싱 로직 불필요.
- **표시**: `office_data.py`의 `EMPLOYEES` 목록에서 Trigger/Maverick/Guardian/Balance의
  `placeholder: True`를 해제. 오피스 UI에서 TRADING/RISK MGMT 존이 잠금 해제되어 카드로 보이고,
  클릭하면 기존 모달 패턴으로 상세 텍스트 표시.

## 에러 처리

기존 애널리스트 파이프라인과 동일한 방식을 따른다: Trigger나 리스크 검토 담당자 중 하나가 실패해도
나머지는 계속 진행하고, 실패한 자리는 기존 패턴대로 에러 문구를 담은 카드로 표시한다. 파이프라인
전체를 막지 않는다.

## 검증

이 저장소는 자동 테스트 프레임워크가 없다(기존 컨벤션과 동일). 각 구현 태스크는 수동 실행 확인
스텝으로 검증한다. 최종 확인: `/scheduled-analysis`(또는 `/daily-report`) 1회 실행 →
`reports/YYYY-MM-DD.md`에 매매 시그널 섹션이 생성됐는지, 오피스 UI에서 TRADING/RISK MGMT 카드가
잠금 해제되고 숫자(진입가/목표가/손절가/포지션%)가 리서치 근거와 앞뒤가 맞는지 육안 확인.

## 문서 갱신

`README.md`의 로드맵 섹션을 아래로 교체한다:

- 1단계: 기존 그대로 유지.
- 2단계: "매매 신호 생성 + 승인 후 실행" → "매매 시그널 생성 + 리스크 검토(크립토 파일럿). 실제
  주문은 사람이 거래소 앱/사이트에서 직접 실행합니다. AI는 거래소 API를 호출하지 않습니다."로 갱신.
- 3단계: 항목 자체를 삭제.
