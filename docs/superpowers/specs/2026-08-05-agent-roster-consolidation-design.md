# 에이전트 구성 축소 (22명 → 13명) — 설계

## 배경 / 문제

현재 애널리스트팀 구조는 데스크(크립토/국내주식/해외주식)마다 애널리스트 4명(기술적분석/시장심리/뉴스·
이슈/펀더멘털) + 리서치 3명(강세/약세/종합) = 7명, 총 21명 + PM 1명 = 22명이다.

[[2026-08-05-hourly-automation-reliability-design]]에서 시간별 자동화가 실패하던 근본 원인 중 하나가
"22명(WebSearch 포함)을 20분 안에 다 돌리려던 시간제한"이었다. 자동화 스케줄 자체는 그 설계에서 고쳤지만,
에이전트 수가 많을수록 비용·실행시간·실패 가능성이 함께 커지는 구조적 문제는 남아있다. 또한 사용자가
직접 검토한 결과, 다음 두 지점이 과설계로 판단됨:

1. **뉴스·이슈(Chain/Scoop/Herald)와 시장심리(Vibes/Mood/Pulse)** — 둘 다 WebSearch로 정성적 정보를
   찾아 해석하는 역할이라 실질적으로 겹치는 부분이 많다.
2. **강세(Ape/Rally/Surge)·약세(Fud/Slump/Drag)·종합(Node/Anchor/Compass) 3인 구조** — 데스크당 3명,
   총 9명이 여기 들어간다. 별도 에이전트로 강제 대립시키는 것은 "종합 담당이 한쪽에 은근히 동조"하는
   것을 막는 효과가 있지만, 1단계(확정 매매 시그널이 아닌 참고용 리포트)의 목적에 비해 비용이 크다.

## 방향

데스크당 4명(기술적분석/펀더멘털/뉴스·심리 통합/리서치 종합) + PM 1명 = 총 13명으로 축소한다.

## 아키텍처

### 데스크당 역할 매핑

| 역할 | 크립토 | 국내주식 | 해외주식 | 비고 |
|---|---|---|---|---|
| 기술적분석 | Candle | Chart | Trend | 변경 없음 |
| 펀더멘털 | Proto | Ledger | Vault | 변경 없음 |
| 뉴스·심리 통합 | Vibes | Mood | Pulse | 이름 유지, 역할 확장 |
| 리서치 종합 | Node | Anchor | Compass | 이름 유지, 역할 확장 |

- **폐지**: `chain.md`, `scoop.md`, `herald.md`(뉴스·이슈 담당), `ape.md`, `rally.md`, `surge.md`(강세
  담당), `fud.md`, `slump.md`, `drag.md`(약세 담당) — 총 9개 에이전트 파일 삭제.
- **역할 확장 — 뉴스·심리 통합** (`vibes.md`/`mood.md`/`pulse.md`): 기존 시장심리 역할에 더해, 폐지되는
  뉴스·이슈 담당이 하던 WebSearch 기반 뉴스 조사를 같은 프롬프트 안에서 함께 수행. 출력 형식에 "관련
  뉴스·이슈" 섹션을 추가.
- **역할 확장 — 리서치 종합** (`node.md`/`anchor.md`/`compass.md`): 기존에는 강세/약세 담당이 각자 낸
  결과를 받아 종합만 했다면, 이제 애널리스트 4명의 결과를 직접 받아 프롬프트 안에서 스스로 강세 논거와
  약세 논거를 세운 뒤 근거 품질을 저울질해 하나의 결론을 낸다(자기 안에서 양쪽 입장을 만들고 비교하는
  구조). 출력 형식에 "강세 논거"/"약세 논거"/"종합 판단" 섹션을 유지해, 대립 구도로 검토했다는 흔적이
  리포트에 남도록 한다.
- **PM (`chief-strategist.md`)**: 구조 변경 없음. 입력이 데스크당 7개(4애널리스트+3리서치) → 4개
  (3애널리스트+1리서치)로 줄어드는 것만 반영. "Node/Anchor/Compass가 이미 강세·약세 근거 품질을 저울질해
  놓았으므로 그 결과를 다시 근거 개수로 뭉개지 말 것"이라는 기존 지시는 그대로 유효(주체만 3인 협업에서
  1인 내부 추론으로 바뀜).

### 오케스트레이션 변경 (`daily-report.md`, `scheduled-analysis.md`)
- 애널리스트팀 병렬 호출: 12개 → 9개(데스크당 3명 × 3데스크)
- 리서치팀: 데스크당 강세·약세 병렬 호출 후 종합 전달(2단계) → 데스크당 리서치 종합 1명 단독 호출(1단계)로
  단순화. 3데스크 리서치 종합 3명은 서로 독립적이므로 병렬 호출 유지.
- PM 호출: 입력 목록만 축소(9+9개 결과 → 9+3개 결과), 흐름은 동일.

### 문서 변경
- `README.md`의 "구성 (AI 직원)" 표를 13명 기준으로 갱신, 폐지된 9명 제거.

## 에러 처리
기존과 동일한 원칙 유지: 데이터에 없는 내용을 지어내지 않고 "확인 필요"로 표기, 매수/매도 확정 지시
금지. 역할이 넓어진 두 그룹(뉴스·심리 통합, 리서치 종합)도 이 제약을 그대로 따른다.

## 테스트/검증
자동 테스트 없이, 변경 후 `/daily-report` 1회 수동 실행으로 확인한다.
- 애널리스트 9명 + 리서치 3명 + PM 리포트가 오류 없이 끝까지 생성되는지
- 뉴스·심리 통합 에이전트 출력에 뉴스 조사 내용이 실제로 포함되는지
- 리서치 종합 에이전트 출력에 강세/약세 논거가 모두 드러나는지 (한쪽만 쓰고 넘어가지 않는지)

## 범위 밖 (다음에)
- 애널리스트 프롬프트 내용 자체의 품질 개선(지표 해석 방식 등)
- 2단계(매매 시그널)·3단계(자동매매) 기능

## 기존 설계와의 관계
[[2026-08-05-hourly-automation-reliability-design]]에서 정한 스케줄(하루 3회, 회당 $3 예산, 55분 시간
제한)은 그대로 유지한다. 에이전트가 22명→13명으로 줄어 비용·시간 여유가 늘어나는 방향이므로 재조정이
필요하지 않다.
